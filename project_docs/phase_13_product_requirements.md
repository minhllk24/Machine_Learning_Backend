## 1. Product Purpose & Architecture Boundaries

The web application serves as the production user interface for the retail SKU-week demand forecasting and replenishment planning system. It consumes the frozen, audited machine learning models and FastAPI backend services developed across Phases 1–12.

### 1.1 Non-Negotiable Product Guardrails
1. **Zero Client-Side Forecasting:** The frontend is strictly a presentation and interaction layer. All model inference, recursive lag updates, and replenishment formulas execute on the backend.
2. **Honest Data Provenance:** Every metric displayed in the interface explicitly identifies its source protocol:
   - `ROLLING_OOF_CV`: 5-fold cross-validation over 40 development weeks.
   - `SINGLE_PASS_HOLDOUT`: Single evaluation across the 8-week holdout (`2011-10-10` to `2011-11-28`).
   - `LIVE_INFERENCE`: Ad-hoc forecast run generated by the backend service.
3. **Mandatory Caveat & Disclaimer Enforcement:**
   - Historical Context: Persistent banner declaring that data spans 2009–2011 UK retail; `current_market_applicability_assessed = FALSE`.
   - Replenishment Planning: Output explicitly labeled `SIMULATION_BASED_ON_USER_ASSUMPTIONS`; no unvalidated optimality claims.
4. **Backend-First Role-Based Access Control:** Frontend routes visually reflect permissions, but all authorization boundaries are strictly enforced at the FastAPI endpoint level.

## 2. User Roles & Permission Model

| Role | Target Persona | Core Capabilities | Restricted Actions |
|---|---|---|---|
| **Admin** | IT Administrator, MLOps Lead | Full management: User provisioning, role assignment, system health monitoring, registry inspection. | Cannot alter frozen model weights or rewrite historical records. |
| **Analyst** | Data Scientist, Demand Forecaster | Run demand forecasts, explore SKU catalog & history, review model evaluation benchmarks, export forecast CSV/XLSX. | Cannot manage user accounts, alter models, or run replenishment planning. |
| **Planner** | Supply Chain Planner, Inventory Mgr | Run demand forecasts, explore SKU demand patterns, execute periodic-review replenishment simulations, download exports. | Cannot manage system users or alter model serving configurations. |
| **Viewer** | Executive, Business Stakeholder | Read-only view: Executive dashboard, SKU catalog, published evaluation leaderboards, approved run history. | Cannot trigger inference, export runs, simulate orders, or modify data. |

## 3. Product Screen Specifications

### 3.1 SCR-01: Authentication & Session (`/login`)
- **Components:** Login card, username/password inputs, role indicator, university branding header, error alert banner.
- **Validation:** Username required; password $\ge 6$ characters; clear error display on HTTP 401 (`INVALID_CREDENTIALS`).
- **Session Lifecycle:** JWT token stored securely in client state with expiration tracking. Automatic redirect to `/login` with `session_expired=true` query parameter upon token expiry.

### 3.2 SCR-02: Executive Dashboard Summary (`/`)
- **KPI Card Grid:**
  - Qualified Panel SKUs: `2,785` (Primary: 1,717; Secondary: 1,068).
  - Cleaned Catalog Merchandise: `4,905` SKUs.
  - Historical Development Span: `96 weeks` (`2009-12-07` to `2011-10-03`).
  - Active Production Champion: `CatBoost__MAE` (WAPE 65.57%, MASE 0.6225).
- **Recent Runs Telemetry:** Live table of recent forecasting executions with status indicators (SUCCEEDED, RUNNING, FAILED).
- **System Disclaimer Banner:** Prominent informational callout regarding dataset era and non-causal attribution.

### 3.3 SCR-03: Interactive Demand Forecasting (`/forecast`)
- **Controls Toolbar:**
  - Model Selector: Dynamically populated with models reporting `serving_status == "READY"` (`CatBoost__MAE`, `CatBoost__Tweedie_p15`, `TiDE_Sequence_v1`). Non-serving models (`LightGBM`, `TFT`) disabled with `CV_ARTIFACT` badge.
  - SKU Selection: Searchable multi-select supporting individual SKU lookup or batch entry.
  - Origin Date: Defaults to latest development cutoff (`2011-10-03`).
  - Horizon Steps: Radio buttons for $H=1$, $H=4$, $H=8$ weeks.
- **Results View:**
  - Dynamic line chart plotting predicted weekly demand across the forecast horizon.
  - Data table showing `sku_id`, `target_week`, `predicted_demand_units`, and cohort tier.
  - Direct Action: "Export to CSV" and "Simulate Replenishment" buttons.

### 3.4 SCR-04 & SCR-05: SKU Explorer & Historical Profile (`/skus`, `/skus/:skuId`)
- **Catalog Search & Filtering:**
  - Search by SKU ID or description string.
  - Cohort filter: All, Mature (Primary), Late-Maturing (Secondary).
  - ABC Classification filter: `ABC_DEMAND_PANEL` (Class A, B, C).
  - SBC Intermittency filter: Smooth, Erratic, Intermittent, Lumpy.
- **SKU Historical Profile Drawer/Page:**
  - Key statistics pill group: Mean weekly demand, zero-demand ratio, unit price range, first observed week.
  - 104-week time-series bar chart illustrating actual sales quantities and lifecycle zero-fill periods.

### 3.5 SCR-06: Replenishment Planning Simulation (`/planning`)
- **Assumption Inputs:**
  - Selected SKU and forecast point estimates.
  - Stock on Hand (units).
  - Incoming Purchase Orders (units).
  - Supplier Lead Time ($L \in [1, \text{horizon}]$ weeks).
  - Safety Stock Buffer ($SS$ units).
- **Indicative Simulation Calculation:**
  $$\text{Net Demand} = \sum_{h=1}^{L} \hat{y}_{t+h}$$
  $$\text{Gross Requirement} = \text{Net Demand} + SS$$
  $$\text{Net Inventory Position} = \text{Stock on Hand} + \text{Incoming Stock}$$
  $$\text{Suggested Replenishment Qty} = \max(0, \text{Gross Requirement} - \text{Net Inventory Position})$$
- **Callout Banner:** Prominent `SIMULATION_BASED_ON_USER_ASSUMPTIONS` badge.

### 3.6 SCR-07: Model Evaluation & Benchmark Leaderboard (`/evaluation`)
- **Tabbed Protocol Views:**
  - Tab 1: 5-Fold Rolling Cross-Validation (40 development weeks, Common Universe 68,680 Primary keys).
  - Tab 2: Single-Pass Final Holdout (8 test weeks, 22,280 Primary keys).
- **Metrics Table:** Model ID, Model Family, Cohort, Horizon, WAPE (%), RMSE, Signed Bias (%), Macro MASE, Clipping Rate (%).
- **Explainability View:** Embedded top SHAP feature importance rankings and non-causal interpretability rules.

### 3.7 SCR-08: Forecast Run History & Secure Export (`/history`)
- **Run Audit Ledger:** Paginated history table displaying `forecast_run_id`, `created_at`, `model_id`, `origin_date`, `horizon_weeks`, `total_records`, and `status`.
- **Export Modal:** Allows requesting instant CSV (RFC 4180 compliant) or formatted Excel (`.xlsx`) export with string-preserved SKU codes and cryptographic SHA-256 validation.

### 3.8 SCR-09: Model Registry & Infrastructure Telemetry (`/registry`)
- **Registry Inspection:** Read-only table of all 78 registered models and baselines. Displays model role, serving readiness, supported horizons, and SHA-256 digest.
- **System Health Probes:** Live status chips reflecting `/health/live` and `/health/ready`.

### 3.9 SCR-10: User Management (`/admin/users`)
- **Admin Management Console:** Paginated table of system accounts, active role assignments, and creation date. Modal dialog to create new users with assigned roles (Admin, Analyst, Planner, Viewer).

## 4. UI Design System Tokens & Aesthetics

To provide a state-of-the-art, premium analytics experience, the interface adheres to a sleek modern design system:

### 4.1 Color System
- **Brand Navy / Primary:** `#1E3A8A` (Deep Blue), `#3B82F6` (Electric Accent)
- **Neutral Dark Background:** `#0F172A` (Slate 900), `#1E293B` (Slate 800 Card), `#334155` (Border)
- **Neutral Light Mode:** `#F8FAFC` (Canvas), `#FFFFFF` (Card), `#E2E8F0` (Border)
- **Semantic Accents:**
  - Success / Ready: `#10B981` (Emerald)
  - Warning / Caution: `#F59E0B` (Amber)
  - Danger / Error: `#EF4444` (Rose / Crimson)
  - Info / Research: `#6366F1` (Indigo)

### 4.2 Typography & Spacing
- **Font Family:** `Inter`, system-ui, -apple-system, sans-serif.
- **Monospace (Data / Hashes):** `'Roboto Mono'`, `Consolas`, monospace.
- **Type Scale:** Display (32px/1.2), H1 (24px/1.3), H2 (20px/1.4), Body (14px/1.5), Caption (12px/1.4).
- **Layout Grid:** 12-column responsive grid with 24px gutters; max-width 1440px.

### 4.3 Component States & Accessibility Target
- **States:** Default, Hover (:hover + transition 150ms), Active/Focused (:focus-visible 2px offset ring), Disabled (opacity 0.4, cursor not-allowed), Loading (skeleton shimmer).
- **WCAG 2.2 AA Compliance:** High contrast text ($\ge 4.5:1$ ratio), visible focus rings, non-color-only status badges, keyboard navigation for all interactive inputs.
